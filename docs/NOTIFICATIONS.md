# Notifications and optional SMS

NotificationService persists deduplicated event keys, unread state and per-channel delivery rows. UI supports in-app/SMS, event selection, Pacific/UTC quiet hours and optional critical quiet-hour override. Disabled in-app preferences hide the feed but retain auditable event history. Normal disabled event kinds are omitted; critical events remain auditable. Default events include option/aggressive open/close, partial fills/rejections, STOP, kill, reconciliation, broker disconnect and daily/weekly reports. SAFE can be explicitly enabled. A 20-second operational monitor records deduplicated sleeve kills, health transitions, configured-broker disconnects and missing/stale/invalid-time account facts; unsafe real account state pauses new risk. Critical events excluded from event preferences remain auditable but do not route SMS. Actual-host/broker/provider failure acceptance is still required.

TwilioSmsProvider implements the [official Messages resource](https://www.twilio.com/docs/messaging/api/message-resource) behind NotificationProvider. Set TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_FROM_NUMBER and SMS_TO_NUMBER only in the protected server environment. Set PRIVATE_UI_URL to the private HTTPS UI. SMS requires preferences.sms and ENABLE_SMS_DELIVERY=true; keep both off until explicit commissioning. React never receives credentials. Report SMS is short and links to the private UI.

Simulation deliveries are always SUPPRESSED_SIMULATION. Delivery claims a row as UNKNOWN **before** the HTTP request, with an atomic claim check against concurrent sends. Success records provider SID; errors/timeouts remain UNKNOWN and are not automatically retried after restart. Reconcile a provider receipt before any manual resend to avoid duplicates. No real SMS was sent during verification; production sender/regulatory/phone-number acceptance remains external work.
