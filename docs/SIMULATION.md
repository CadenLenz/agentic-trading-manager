# Isolated full-system simulation

Press the top-bar RUN FULL SYSTEM TEST once; a dedicated run starts and the Simulation Control Room opens. Speeds: 1x (roughly 100 seconds), 5x, 20x and MAX. Change speed during a run, cancel, select retained history or export JSON. The view shows assertions, virtual NAV/BP, three sleeve cards, recorded account equity, a live event feed and orders/fills/risk/notification/report details. Scenario timestamps are accelerated presentation time; underlying fixture service clocks are real monotonic wall-clock calls, not an exchange backtest clock.

The run records current rich/legacy/account/strategy/sleeve configuration metadata. Main lifecycle uses the rich-risk snapshot with an explicitly synthetic $50k account; independent negative scenario branches use known deterministic defaults so every boundary can be tested. Options permission is enabled only inside the fixture graph. Therefore success proves these service contracts, **not every possible operator configuration or profitable trading**. A restrictive rich configuration can correctly make a main lifecycle assertion fail. Do not loosen production risk just to obtain a pass.

Each run constructs a fresh DB and fixture SimulationTradingBroker/market provider. No live adapter, network transport, credentials, research fetch, paid AI or real SMS is constructed. Application ledger cash/positions/fills are untouched; application writes are only run/event/evidence metadata. Automated isolation tests replace global fetch with a throwing spy and verify zero requests plus unchanged application cash/positions. The full suite also checks duplicated execution/fills and restart without replay.

65 assertions cover all three researched/previewed/manual-approved entry paths; equity MARKET/LIMIT/rejection/partial/cancel/profit/stop-triggered CLOSE; Level 2 option long call/put, naked/covered/CSP validation, collateral/OI/spread/DTE and partial contracts; unavailable Greeks versus explicitly synthetic movements; losing/profitable closes; reviewed expiry/assignment/exercise; configuration/sizing/exposure/freshness; outages/UNKNOWN/timeout/pause/STOP/60% kill; transfers/basis/cash flows/split; persisted DB restart and reports/notifications/charts. Synthetic source labels never claim real current research. API/Pi restart coverage is service/database contract simulation, not an executed physical reboot or subprocess API test.

`npm run test:system` uses a newly created OS temporary directory, prints counts/failures and retains DBs plus `simulation-report.json`. UI runs persist in DATA_DIR/simulations, with run metadata in simulation_runs/simulation_events. A startup marks interrupted runs INTERRUPTED; graceful shutdown cancels and waits before closing the DB. Evidence is valid only while critical configuration hash matches, and expires after 24h. No simulation can activate LIVE.
